## Known Constraints & Considerations

### 1. Framework Initialization
- SelfHealingRegistry instantiated in display-runtime (app-specific)
- Global registry accessed by command-service (for preflight)
- Both run in same Node process (no IPC needed)

### 2. Path Resolution
- Validator path: `/opt/otto-display-system/auto-update.sh` (deployed)
- Canonical template: Searched in `runtime/` or `tools/pi/` (relative to workspace)
- Repair writes to: `/opt/otto-display-system/auto-update.sh`

### 3. Environment Variables
- `OTTO_AUTO_REPAIR_SCRIPTS`: Controls repair enablement (default=true)
- Can be set in auto-update.sh, systemd unit, or export in shell

### 4. Permissions
- Repair requires write access to `/opt/otto-display-system/`
- Running under: systemd service (typically root or otto user)
- Bash functions require correct syntax (both `foo()` and `function foo` supported)
